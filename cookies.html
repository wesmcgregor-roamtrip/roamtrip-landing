RoamTrip

Cookies and Tracking

Review draft: 16 October 2026. Validate the released app and deployed website before publication.

Mobile app

RoamTrip uses local app storage for sign-in sessions, preferences and offline data. Native SDKs can process data without using browser cookies. Supabase supports accounts and stored content; RevenueCat manages subscriptions using an app user identifier. Map, weather and other feature providers receive the information necessary for their requests.

In the revised app, Sentry session replay, automatic logs and performance tracing are disabled. Crash reporting may still send diagnostic and device information. User, request, extra and breadcrumb fields are removed before error events are sent, but this is not a guarantee of anonymous data: error messages, stack traces and infrastructure logs need runtime review. Older installed versions may use the previous replay configuration until updated.

No advertising SDK or cross-app advertising use was identified in the reviewed dependency/configuration sample. Do not treat that code review as proof of every deployed SDK's behaviour. A verified data inventory is required for final tracking and store declarations.

Website

The reviewed landing-page script handles animation and scrolling; it does not set analytics cookies. The page loads Google Fonts, which sends network requests to Google. Hosting providers may keep access logs. Signed-in Scout/admin services are separate surfaces whose cookies and storage must be inventoried before this policy is presented as covering them. A blanket claim that RoamTrip never uses cookies or individually identifiable data is inappropriate.

Choices and contact

Use device permissions to manage location, photos/camera and notifications; revoke permissions in device settings. Manage browser cookies/storage in the browser. Some features need these permissions or storage to work. Contact support@roamtrip.mobile for privacy questions.
